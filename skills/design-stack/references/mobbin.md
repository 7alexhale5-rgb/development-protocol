# Optional Mobbin research

Use a connected reference service during Step 4, not as a second design process. These routes
were rechecked against primary documentation on 2026-10-20. Recheck the actual account, current
server schema, pricing and rights before using them; installation is not connection proof.
A public-product search and attributed screenshots are the free fallback when no account exists.

## Route by the question

- One interface state: `search_screens`, standard mode first, for the supported platform.
- A sequence of actions: `search_flows`; inspect previews and retrieve missing steps when needed.
- A website region: `search_sections`, such as pricing or navigation.
- Deep search: only after standard results leave a material gap and current usage permits it.

Start with one natural-language intent and a small result count. Use the actual exposed schema,
not invented parameters. Exclude private client data from queries. Keep task intent and output
destination consistent. Inspect image pixels before describing them. Retain the source URL,
app, screen or flow identity, retrieval time, chosen pattern and reason in the existing brief.
For requested exports, use the supported high-resolution asset rather than a thumbnail. Check
expiry and rights. Access does not license copying another product's code, brand or assets.

## Available plan features

[Pricing checked on 2026-10-20](https://mobbin.com/pricing) lists Pro access to apps and sites,
flows, animations, collections, downloads, version history, Deep Search and MCP. Shared team
collections and general API access belong to Team or above. Pro is not an API credential.
This documents plan features, not the current user's billing or remaining credit balance.

[The MCP feature reference](https://docs.mobbin.com/mcp/features) lists the three search tools
above, preview plus high-resolution images, and inline galleries in supported Claude and Codex
desktop clients. Image URLs expire after 30 days. Search access does not expose every website
feature as a tool. Use the supported gallery for reference selection; deliver the actual working
plan in the active desktop app browser under the shared protocol contract.

## Account and capability boundaries

The documented remote endpoint is https://api.mobbin.com/mcp with Streamable HTTP and OAuth.
Use the supported client connection flow. An optional server needs no invented API-key variable.
Inspect existing client connections before adding one. Repeated account-page entries alone do
not prove duplicate active transports; identify their owner before revoking anything.

[The Claude Code guide](https://docs.mobbin.com/mcp/clients/claude-code-cli) recommends
sharing the Claude desktop/web connector. A missing explicit CLI server entry alone does
not disprove that shared route. Check the existing connector and a real returned result
before adding a separate CLI-only transport; avoid duplicate carriers.

Plan membership, connector access and a general API grant are different facts. Verify the actual
plan and available capabilities rather than assuming Team rights from Pro. Search results do
not prove that the connector can edit collections, export design layers, fetch source code or
reproduce motion. Website-only features require their own supported path. Each host needs one
real returned result before its connection is called verified; one host's result proves only it.

Review current Billing and Usage before credit-consuming work, including other callers on the
account. A dated beta allowance does not mean permanent unlimited use. Missing usage stays
unknown. Respect rate limits and retry instructions; do not repeatedly spend on a missing provider.
Authentication errors use the existing OAuth route. No matches means revise the query or choose
an attributed alternative. Neither case waives functional, accessibility or rendered-design proof.

Keep plans and comparisons in the active desktop app browser. The existing authenticated browser
may support account administration; it is not the visual planning delivery surface.
